# Post-#79 DC operating point with the OSDI varactor, 27 C (issue #252)

Append-only. Testbench: `klt-sim/op-only/` (request `request-op-27C.json`, the netlist body and inductor model
copied unchanged from `klt-sim/hot-startup/`, and the retained evidence under `evidence/`:
generated `corner.cir`, `batch-receipt.json`). The raw `ngspice.log` is in the artifact store, pointed at by
`manifests/artifacts/oscillator-core-op-only-20261105-klt-sim-f2ebf7e3f575.manifest.json` (sha256 `2b56db4d...1104c`,
280 bytes; re-collected from fleet job `klt-sim-f2ebf7e3f575` and checked against the quoted lines below).

## Question
The reporter of #252 saw "The temperature limiting function received NaN" and no operating point for
`design/vco.spice` at 27 C on a local ngspice-47 build. Does the netlist reach an OP on ngspice-46?

## Method
- Netlist: `design/vco.spice` (sha256 `090983d6...49404`, main @ `504adb5`), device section only, same body
  as `klt-sim/hot-startup/vco_core_body.spice` (byte-identical). That body **does contain**
  `.ic v(OUTP)=3.305 v(OUTN)=3.295` (line 47), so the `.ic` is present in this run; whether it has any effect on a
  single `op` on this route was **not isolated** (no re-run without it). No `.nodeset`, no option overrides.
- Corner: tt (`mos_tt` / `hbt_typ` / `cap_typ`), Vctrl 1.65 V, **27 C** (TNOM 27 C). Analysis: a single `op`.
- OSDI: `options.osdi_preload` = `$PDK_ROOT/ihp-sg13g2/libs.tech/ngspice/osdi/mosvar.osdi`, resolved on the runner
  to `/opt/pdk/ihp-sg13g2/libs.tech/ngspice/osdi/mosvar.osdi`.
- Route: one unit, `klt sim --backend batch` (no local `mosvar.osdi` exists on this host, so a local run was not
  possible). Fleet job `klt-sim-f2ebf7e3f575` (c7i.8xlarge spot, us-east-1a), ngspice-46, client klt 0.9.1.dev17.
- PDK: runner `ihp-sg13g2` reported as `fetched:0.3.0`; the runner stamp is unreadable (`not_comparable`), so
  equality with `sim/pdk.json` is not verified. Overlay state: **none applied** (no `svaricap_dsubw_vj` overlay;
  runner's stock v0.3.0 models, vj = 0.1). OSDI/compiler digests: not reported by the runner and not measured here.

## Result
**The OP converges.** `ngspice.log` shows `Doing analysis at TEMP = 27.000000 and TNOM = 27.000000`, one data row,
and `ngspice-46 done`, with no NaN message, no gmin/source stepping and no error. klt reports the corner `[pass]`
in 0.168 s.

## Does the reporter's NaN reproduce?
**No, not on ngspice-46 at 27 C on this route.** Taken with the 27 C `tran` in the #280 record this is a second
independent observation of a working 27 C start. The reporter's failure is therefore, as far as measured,
specific to their setup. ngspice-47 was **not** run here, so attributing it to 46-vs-47 stays unmeasured.
Bisection was not needed (nothing to bisect).

## Classification
Closest to **(a) simulator-build / setup dependent**, with this caveat, which is a difference I did not control:
the reporter set `ngbehavior=hsa`; this run's log opens with `Note: No compatibility mode selected!` (klt could
not set it on this route), so compatibility mode is a second candidate difference besides 46 vs 47. Neither is
tested. No evidence of (b) a PDK defect or (c) a netlist change; `design/` and `spec/` are untouched.

## Limits
- The log has no printed node voltages: the claim is "an OP was produced without error", not a comparison of OP
  values with the reporter's `v(tail)` = 2.516 V (varactors-removed case).
- One corner, 27 C only. The 125 C start-up abort is in the #280 record and was not re-measured.
- klt reported the **job** as `failed` (`job command exited 4`) while the one corner passed; cause not traced
  (see the klayout-tools friction issue).
