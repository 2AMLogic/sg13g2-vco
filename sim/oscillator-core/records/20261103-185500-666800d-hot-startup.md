# Hot (125 C) start-up classification, and OSDI-on-fleet reproduction (issue #280)

Append-only. Testbench: `klt-sim/hot-startup/` (requests, netlist body, and for every unit the
generated deck, ngspice log and klt report under `evidence/`).

## Method
- Netlist: `design/vco.spice` (sha256 `090983d6...49404`, main @ `666800d`), device section only
  (same body recipe as `klt-sim/README.md`), plus `.ic v(OUTP)=3.305 v(OUTN)=3.295`.
- Corner: **tt / hbt_typ / cap_typ**, Vdd 3.3 V, Vctrl 1.65 V, **T = 27 C (control) and 125 C** (TNOM 27 C).
  One process corner by design: this classifies start-up; it is not a PVT grid.
- Analysis `tran 1p 2n 0 2p` (2 ns; start-up is inside the first ns). OSDI varactor through
  `options.osdi_preload = $PDK_ROOT/ihp-sg13g2/libs.tech/ngspice/osdi/mosvar.osdi` (resolved on the runner).
- Variant **noop**: bare `tran` (what `klt sim` generates). Variant **op**: `analysis_steps` = `op`, then `tran`.
- Batch fleet (`--backend batch`, `--submit-only` then `--attach`); no local grid. ngspice-46 on the runner,
  runner klt 0.8.0, client klt 0.8.1.dev1307+g4458c964e512. Runner PDK `ihp-sg13g2` at `/opt/pdk`
  (stamp unreadable, so not comparable to the host's PDK).

| variant | fleet job id (`environment.remote.job_id`) | instance |
|---|---|---|
| noop | `klt-sim-26f15c45ed52` | m7i.4xlarge spot, us-east-1c |
| op   | `klt-sim-cb3f711437a5` | c7i.8xlarge spot, us-east-1b |

## Results (measured)
| variant | 27 C control | 125 C |
|---|---|---|
| noop | starts; Vdiff pk-pk 0.5844 V over 2 ns | **abort at first timepoint**: `Timestep too small; initial timepoint: trouble with xq1:npn13g2v_nx_vbic-instance q.xq1.qnpn13g2v` |
| op   | starts; Vdiff pk-pk 0.5844 V | **same error**. The `op` step itself converged at 125 C (dynamic gmin stepping completed); the following `tran` aborts at its initial timepoint |

At 125 C in both variants ngspice prints once, before the op: `The temperature limiting function
received NaN.` It does not appear at 27 C.

## Classification
**Not start-up only, as far as the two variants tried show (measured); cause inferred, not traced.**
A converged `op` before the `tran` does not change the outcome or the error, so the failure is not
caused by `klt sim` omitting an `op`. The NaN from the temperature limiter is the inferred cause; this repo
already recorded a NaN `dsubw` card above ~52 C (`bn-substrate-tank/`), but the NaN here was not traced to a
device, and the diagnostic names the HBT `xq1`. This is outcome (a)/(c) mixed: (a) for "not cured by an `op`",
(c) for "intrinsic to the models". Not tried: no-`.ic`, `uic`, `.nodeset`, gmin/itl options, a different
TNOM, self-heating off. Follow-up is out of scope for #280.

## OSDI on the fleet (measured)
Reproduced here: **yes.** The `$PDK_ROOT/...mosvar.osdi` form was expanded on the runner to
`/opt/pdk/ihp-sg13g2/libs.tech/ngspice/osdi/mosvar.osdi`, loaded, and the 32-varactor deck ran to completion at
27 C in both jobs (~0.87 s). The jobs report overall `failed` (exit 4) only because the 125 C unit errored.

## Limits
Single process corner, single Vdd/Vctrl, 2 ns window: start-up classification, not a result for any spec row.
